# M22: A large names list from a public dataset

## The concept in one paragraph

M21 showed that the redactor can only mask names its list knows, and on fresh names that was almost none (57%, the same as spaCy alone). M22 changed the list, not the rules. It generated a list of about **49,000 Indian name words** from **Wikidata**, the public, CC0 (public-domain) database behind Wikipedia, and checked it on **N6**, a third held-out set committed before anything was downloaded. Recall went from **67% to 99%**, and plain English text gained no new masks. Getting there needed three things that are new in this milestone:
- **choosing a dataset by its licence and provenance**, not just its size;
- **a common-words filter**, so names that are also English words ("Mark", "Joy") don't hide ordinary text;
- **a set lookup instead of a giant regex**, so 49,000 names cost microseconds, not seconds.

## Web-dev analogy

- **A licence check before a dataset** is the same as checking an npm package's licence before you vendor it into a public repo. A GPL or "research only" file can't just be copied into your repo, however useful it is.
- **A set lookup vs a regex alternation** is `new Set(names).has(word)` vs `new RegExp(names.join("|")).test(text)`. The Set is a hash table: one jump, whatever its size. The regex tries alternative after alternative.
- **A generated file with a build script** is a lockfile or a Prisma client: never edited by hand, always regenerated by a committed script, with its source written in the header.
- **Provenance** is your `package.json` `repository` field. The list says where every word came from and under which licence.

## What was built (file by file)

- **`tests/name_cases.py`:** N6 (40 fake held-out names, 8 also in ALL CAPS), N6_LOWERCASE and O6 (30 ordinary lines a big list might over-mask: films, trains, temples). All committed first, in `0805191`.
- **`pseudo_hands/core/name_recognizers.py`:** the same three rules, now as a small Presidio `EntityRecognizer`. A regex finds name-*shaped* words; a set says if they're listed. It loads both lists, and either one missing fails closed.
- **`pseudo_hands/build_names_list.py`** (new): a maintenance tool you run by hand. It downloads Wikidata labels and a spelling dictionary into `%LOCALAPPDATA%\Pseudo\names_sources\` and writes the list. It's the only names code that touches the network; `redact()` stays offline.
- **`pseudo_hands/core/indian_names_large.txt`** (new, generated, 465 KB): 30,851 first-name words and 18,643 surname words, with the source and CC0 licence in its header.
- **`tests/test_redactor_m22.py`** (new): R2 and R3 on N6, the licence header, fail-closed, a ceiling on over-masking, and the "Lone" gap.
- **Docs:** PRD M21/M22, D21 and the new D22, ARCHITECTURE, the `pseudo_hands` README.

## Walkthrough of the key code

**1. Choosing the dataset.** Seven candidates were checked and one was chosen. The main reasons against the others:

| Dataset | Why not |
|---|---|
| Electoral-roll surname lookup (1.76M names) | Its source terms say "research purposes… university ID" only |
| `name-dataset` (730k first names) | Built from the 2021 Facebook leak: a privacy tool shouldn't stand on leaked data |
| A Hugging Face "1.5M Indian names" list | No provenance at all |
| Lok Dhaba (election candidates) | Licence couldn't be verified; its site refused connections |

Wikidata won because it is **CC0**: anyone may copy it, so the generated list can live in this public repo.

**2. The query** (`build_names_list.py`): every person whose citizenship is India, British Raj or Dominion of India.
```python
VALUES ?country { wd:Q668 wd:Q129286 wd:Q1775277 }   # India, British Raj, Dominion of India
?person wdt:P27 ?country ; wdt:P31 wd:Q5 ; rdfs:label ?label .
```
A label like "Sachin Tendulkar" is split into words. The last word is filed as a surname, the others as first names. The file holds **words, never full names**.

**3. The common-words filter:**
```python
def keep(word: str, common: set[str]) -> bool:
    return len(word) >= 3 and word not in HONORIFICS and word not in LEFT_OUT and word.lower() not in common
```
`common` is every lowercase entry in the en_GB spelling dictionary. "Mark" is dropped because "mark" is an ordinary word. That keeps "Mark as read" readable, at a price: "Lone", a real Kashmiri surname, is dropped too ("lone"). It was put into N6 on purpose to show that price.

**4. The set lookup** (`name_recognizers.py`):
```python
"listed_name": rf"(?=(?P<span>\b(?P<name>{WORD})\b))",
...
if match.group("name") in self.listed:
```
The regex only knows the *shape* of a name (Capitalized or ALL CAPS). The set knows the names. The `(?=...)` lookahead lets matches overlap, so a rejected candidate ("Hello S.") can't hide a real one right after it ("S. Ramesh"). Before swapping, the new code was compared with the old on 2,039 fake lines: every line was masked the same way.

**Two things to know:**
- **"Durga Puja" now masks both words:** "Puja" is a surname on Wikidata. It still fails closed (D21), but the pinned test output changed.
- **Labels on ties are random.** When spaCy says LOCATION and the list says PERSON for the same word with equal scores, Presidio picks by hash order, so "Pooja" is [PERSON] in one run and [LOCATION] in the next (shown with 4 different `PYTHONHASHSEED`s, on the old code too). The text is masked either way. It's now in the backlog.

<details>
<summary>Answers</summary>

1. Its source data is only for research by people with a university ID, and its maintainers say to check those terms before redistributing. Pseudo's repo is public and it isn't research, so that list can't be committed or relied on.
2. Python's regex engine tries the alternatives one after another at every position, and compiling 50,000 alternatives takes seconds. A set hashes the word and jumps straight to the answer, whatever its size.
3. It keeps ordinary words that are also names readable ("Mark as read", "Joy of coding"). It costs real names that are also words: "Irfan Lone" keeps "Lone".
4. If N6 had been written after seeing the list, the names could (even unconsciously) have been picked from it, and 99% would prove nothing. Committing first fixes N6 in git history, before anything could influence it.
5. `test_r10_ordinary_words_masked_stay_within_what_m22_measured` pins the words masked on O6 and N5 as a ceiling. A rebuilt list that hides more ordinary words fails that test.

## How this connects to Pseudo's final architecture

- **Recall on Indian names is now measured at 99% on unseen names**, so screen text and, later, memory notes (roadmap 6) leak far fewer names. Lower case and names Wikidata doesn't know remain gaps, and your own `indian_names.txt` and `redaction_terms.txt` still cover the people who matter most.
- **The pattern repeats:** a public dataset, checked for licence and provenance, turned by a committed script into a generated file that the offline core only reads. The places list could grow the same way.
- **Safety stays next to the tools (D11):** both lists load inside `pseudo_hands` core and fail closed, so every brain (Pseudo's own, Claude Code, Hermes) gets the same protection.
